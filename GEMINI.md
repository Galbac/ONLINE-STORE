# GroceryStore Engineering Guidelines & Quality Standards

Этот файл является фундаментальным руководством для Gemini CLI при разработке как бэкенда, так и фронтенда в проекте GroceryStore.

---

## 1. Общие принципы разработки

1. **Автономность и надёжность**: Реализовывать задачи под ключ без лишней воды, сохраняя архитектурную целостность системы.
2. **Нулевой регресс**: Перед внесением изменений всегда анализировать существующий код, схемы и зависимости.
3. **Строгая типизация**: Никаких `Any`, `as any` или подавления линтеров/тайпчекеров без крайней необходимости.

---

## 2. Стандарты Frontend и UI/UX (Высокий уровень дизайна)

Стек фронтенда: **Next.js (App Router), TypeScript, Tailwind CSS, Radix UI / Shadcn UI primitives, Framer Motion, Lucide Icons, TanStack Query / SWR**.

### 2.1. Визуальный дизайн и эстетика (Premium Look & Feel)
- **Современная эстетика**:
  - Чистые отступы (модульная сетка 4px/8px), сбалансированная типографика (читаемые шрифты, четкая иерархия заголовков `text-2xl`, `text-lg`, `text-sm`).
  - Тонкие и аккуратные границы: `border border-border/40` или `border-neutral-200 dark:border-neutral-800`.
  - Эффект глубины и стекла (soft shadows, subtle backdrop-blur `backdrop-blur-md bg-background/80`).
  - Продуманная палитра: нейтральная база с акцентным цветом бренда (свежий зеленый/изумрудный для Grocery Store: emerald/green).
- **Микроинтеракции и плавность**:
  - Все интерактивные элементы (кнопки, карточки, инпуты) должны иметь плавные переходы: `transition-all duration-200 ease-in-out`.
  - Hover/Active/Focus состояния: мягкий `hover:shadow-md`, `hover:-translate-y-0.5`, четкое фокусное кольцо для a11y (`focus-visible:ring-2 focus-visible:ring-primary`).
  - Микро-анимации на Framer Motion для открытия модалок, выпадающих списков, drawer корзины и добавления товара в корзину (bounce/scale feedback).

### 2.2. Обязательные состояния интерфейса
Для каждого экрана и компонента ОБЯЗАТЕЛЬНО реализовывать:
1. **Loading State**: Вместо унылых крутилок использовать скелетоны с эффектом мерцания (`Skeleton` / shimmer effects), повторяющие реальную форму контента (карточки товаров, таблицы, списки).
2. **Empty State**: Если товаров, заказов или результатов поиска нет — показывать привлекательный пустой экран с понятной иконкой, описанием и кнопкой действия (CTA, например: «Перейти в каталог», «Сбросить фильтры»).
3. **Error State**: Понятное сообщение об ошибке с кнопкой «Повторить попытку» (`Retry`), а для фоновых ошибок — аккуратные всплывающие Toast-уведомления (Sonner / React-Hot-Toast).
4. **Disabled / Pending State**: Кнопки при отправке формы блокируются, показывают спиннер и меняют текст («Сохранение...»).

### 2.3. Компоненты E-Commerce
- **Карточка товара**:
  - Четкое изображение с `next/image` (`object-cover`, fallback placeholder при ошибке).
  - Бейджи скидок/акций/новинок с контрастным стилем.
  - Цена: текущая крупно, старая зачеркнутая серым цветом.
  - Быстрое добавление в корзину с переключением на счетчик количества (+/-).
  - Кнопка добавления в избранное (heart icon с анимацией клика).
- **Корзина и Чекаут**:
  - Выдвижная панель (Drawer/Sheet) с быстрым просмотром и подсчетом итогов.
  - Пошаговый чекаут: Адрес / Самовывоз -> Время доставки -> Оплата -> Подтверждение.
- **Каталог и Фильтры**:
  - Адаптивные фильтры (на десктопе боковая колонка, на смартфонах — bottom sheet / drawer).
  - Мгновенный поиск с debounce (300ms) и подсветкой совпадений.

### 2.4. Производительность фронтенда
- Использовать React Server Components (RSC) по умолчанию. `'use client'` только там, где есть состояние, хуки браузера или интерактивность.
- Оптимизация картинок через `next/image` с обязательными размерами и lazy-loading.
- Динамический импорт (`next/dynamic`) для тяжелых компонентов (карты, графики, модалки оплаты).

## 3. Стандарты Backend (FastAPI, Dishka, SQLAlchemy, Alembic)

Стек бэкенда: **Python 3.12, FastAPI, Dishka (IoC/DI), SQLAlchemy 2.0 (asyncio), PostgreSQL (asyncpg), Redis, Alembic, Pydantic v2**.

### 3.1. Архитектура слоёв (Strict Layering)
1. **API Router (`source/api/`)**:
   - Только маппинг HTTP-запросов, вызов Dishka-интеракторов или сервисов и возврат Pydantic DTO.
   - Никаких прямых SQL-запросов или бизнес-логики в роутерах.
2. **Interactors (`source/interactors/`)**:
   - Единая точка входа для сценариев использования (Use Cases).
   - Инкапсулируют бизнес-правила и координируют репозитории, внешние сервисы и коммитер.
3. **Services (`source/services/`)**:
   - Вспомогательная логика: авторизация (JWT, пароли), интеграции (1С, платежи, медиа), кэш.
4. **Repositories (`source/repositories/`)**:
   - Чистый доступ к данным через `AsyncSession`.
   - Методы возвращают доменные сущности/модели SQLAlchemy.
   - Избегать проблемы N+1: всегда использовать `selectinload` или `joinedload` для связей.
5. **Commiter (`source/common/commiter.py`, `source/db/sa_commiter.py`)**:
   - Транзакционность и коммит изменений в БД происходят через `Commiter.commit()`, инжектируемый через Dishka.
6. **Dishka IoC (`source/ioc.py`)**:
   - Все новые зависимости, репозитории, сервисы и интеракторы ОБЯЗАТЕЛЬНО регистрируются в Dishka Provider с правильным скоупом (`Scope.REQUEST` для сессий/репозиториев/интеракторов, `Scope.APP` для пулов и настроек).

### 3.2. Миграции Alembic (`migrations/versions/`)
- Строгий нейминг файлов: `YYYYMMDD_NNNN_<описание>.py` (где NNNN — порядковый четырехзначный номер).
- Обязательная реализация функций `upgrade()` и `downgrade()`.
- Использование `server_default` для обязательных новых колонок в существующих таблицах.
- Проверка консистентности моделей `source/db/models/` и схемы БД.

### 3.3. Валидация и схемы (Pydantic v2)
- Разделять схемы на `Create`, `Update`, `Response` (Read).
- Использовать `model_config = ConfigDict(from_attributes=True)` для сериализации моделей SQLAlchemy.
- Валидация входных данных на уровне типов (EmailStr, PositiveInt, Field(min_length=...)).

## 4. Команды проверки качества

При внесении изменений в бэкенд:
```bash
poetry run pytest
```
Если редактировались миграции или модели:
```bash
poetry run alembic check
```
Для фронтенда (при наличии каталога фронтенда):
```bash
npm run lint && npm run type-check && npm run build
```
