# Grocery Store

## Docker

Dev:

```bash
docker compose -f docker-compose.dev.yml up --build
```

Prod:

```bash
docker compose -f docker-compose.prod.yml up --build -d
```

### Настройка домена и SSL (Nginx + Let's Encrypt / Certbot)

1. В файле `.env` укажите ваш домен и почту:
```env
DOMAIN_NAME=yourdomain.com
CERTBOT_EMAIL=admin@yourdomain.com
```

2. Для первичного получения SSL-сертификата выполните скрипт:
```bash
./scripts/init_ssl.sh
```
Скрипт создаст временный самоподписанный сертификат для первого старта Nginx, запросит боевой сертификат Let's Encrypt через ACME-challenge и перезагрузит Nginx с валидным SSL.

3. **Автообновление**: сервис `certbot` в `docker-compose.prod.yml` автоматически каждые 12 часов проверяет срок действия сертификатов и обновляет их без простоя.

### Автоматические бэкапы базы данных

В `docker-compose.prod.yml` встроен автономный сервис `db_backup`:
* Создает сжатый дамп (`.sql.gz`) каждые **6 часов** (настраивается через `BACKUP_INTERVAL_HOURS`).
* Сохраняет файлы в директорию `./backups/postgres` на сервере.
* Автоматически удаляет бэкапы старше **14 дней** (настраивается через `BACKUP_KEEP_DAYS`).

Ручное создание бэкапа в любой момент:
```bash
./scripts/backup_db.sh
```

API и сайт будут доступны по адресу: `https://yourdomain.com`.

Проверка:

```bash
curl https://yourdomain.com/health
```

Остановка dev/prod:

```bash
docker compose -f docker-compose.dev.yml down
docker compose -f docker-compose.prod.yml down
```

## Admin Products

Ручные изменения остатков через `PATCH /api/admin/products/{product_id}/stock` могут быть перезаписаны следующей синхронизацией с 1С.

## Несколько магазинов

- Ассортимент задаётся записями `product_stocks`: отсутствующая запись означает, что товар не продаётся в филиале; нулевой остаток означает, что он закончился.
- `stock_quantity` — доступный для продажи остаток, `reserved_quantity` — резерв заказов. Резерв отдельно вычитать из доступного остатка не нужно.
- Цена филиала хранится в `product_stocks.price`. Если она не задана, используется общая цена товара. `old_price` относится к цене того же филиала.
- В редакторе товара есть блок «Цены и остатки по магазинам». API: `GET /api/admin/products/{product_id}/stores`, `PATCH /api/admin/products/{product_id}/stores/{store_id}`. Передача `price: null` возвращает общую цену.
- Витрина передаёт `store_id` в запросах каталога и заголовок `X-Store-ID` в запросах корзины и заказа. Заказ резервирует остаток выбранного магазина; отмена возвращает его туда же.
- Для 1С задайте уникальный `external_1c_id` филиала через API настроек пунктов выдачи. Импорт цен (`/api/integration/1c/prices`) и остатков (`/api/integration/1c/stocks`) принимает `warehouse_external_1c_id` в каждой позиции. Неизвестный филиал отклоняется, его данные не записываются как общие.
- Поле `expected_cart_total` при создании заказа позволяет отклонить покупку, если сумма корзины успела измениться. Фронтенд передаёт его автоматически.

Существующие остатки сохраняются. Отдельные цены не генерируются: их нужно задать в админке или загрузить из 1С. Перед запуском обновлённого бэкенда выполните `alembic upgrade head`.

### Корзина и избранное по магазинам

Корзина (включая промокод) и избранное привязаны к текущему `X-Store-ID` / `store_id`. Без явного выбора используется первый активный магазин по `sort_order`, затем `id`. Миграция `20261005_0076` сохраняет прежние списки за последним магазином корзины (при его отсутствии — за первым активным магазином), без копирования в другие магазины.

Товары без остатка остаются в списках с предупреждением; их сумма равна нулю. В заказ и резерв попадают только доступные товары. После оформления недоступные позиции сохраняются в корзине. При недостаточном остатке для выбранного количества оформление требует изменения количества.
