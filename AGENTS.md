# AGENTS.md

Общие правила для Codex в этом проекте.

## Стиль ответа

- Отвечай на русском языке, кратко и по делу.
- Не добавляй лишнюю воду, комплименты, длинные вступления и очевидные объяснения.
- Если задача простая, дай короткий ответ или сразу внеси изменение.
- Если работа затрагивает код, в финале кратко укажи, что изменено и как проверено.
- Если что-то не удалось проверить, скажи об этом прямо.

## Обязательный порядок работы

Перед любыми изменениями сначала проанализируй проект:

1. Посмотри релевантные файлы и структуру каталогов.
2. Найди уже существующие паттерны, зависимости, стиль кода и соглашения.
3. Пойми, где именно должна быть правка.
4. Только после этого меняй файлы.

Нельзя писать код "с балды", создавать новые абстракции или менять архитектуру без проверки существующего подхода.

## Работа с кодом

- Следуй текущей структуре проекта: `source/api`, `source/db`, `source/interactors`, `source/services`, `source/schemas`, `source/tests`.
- Предпочитай уже существующие паттерны проекта новым решениям.
- Не делай широкий рефакторинг, если он не нужен для задачи.
- Не трогай чужие или несвязанные изменения.
- Не удаляй код и файлы без явной причины.
- Для ручных правок используй минимальные точечные изменения.
- Комментарии добавляй только там, где без них код реально сложнее понять.

## Python-проект

- Проект использует Python 3.12 и Poetry.
- Основные зависимости: FastAPI, Alembic, async SQLAlchemy.
- Учитывай async-подход в базе данных и сервисах.
- Для поиска используй `rg` / `rg --files`, если доступны.
- Перед запуском команд проверяй, есть ли подходящий скрипт или настройка в `pyproject.toml`.

## Проверка

- После изменений запускай релевантную проверку, если она есть и доступна.
- Не запускай тяжелые или сетевые команды без необходимости.
- Если тестов или команд проверки пока нет, проверь хотя бы синтаксис/импорты там, где это уместно.
- В финальном ответе укажи выполненную проверку.

## Коммуникация при работе

- Если нужно принять техническое решение, сначала коротко объясни основание.
- Если данных не хватает, сначала попробуй найти ответ в проекте.
- Спрашивай пользователя только когда без ответа нельзя безопасно продолжить.
- Не растягивай ответ: максимум конкретики, минимум текста.
